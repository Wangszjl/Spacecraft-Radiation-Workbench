# 按能段分层的 TID 屏蔽扫描

`tools/stratified_tid.py` 为现有 Geant4 屏蔽扫描提供固定预算的分层抽样。它把每种入射粒子的连续能域划成无缝且不重叠的能段，为每段配置历史数。段内仍按原始谱形抽样，保留线性或分箱常数插值；边界穿过原能箱时，只切开能箱，不重新拟合谱。所有能段必须覆盖原谱的全部范围。

每段用自己的物理通量或注量归一化，历史数只决定抽样精度。以通量工程为例，段内预期入射数为 `πR² × 时长 × 段积分通量`（R 用 cm）。脚本从已验收的单段输运记录复算平均沉积、剂量和标准误；各段剂量直接相加，已观测方差按独立运行假设相加。分配更多历史的段不会因此得到更大的物理权重。

任何零命中段都会令合计标准误和相对标准误留空；`observed_standard_error_Gy` 只描述已观测沉积的统计量。它不包含未观察到的贡献，也不是上界。用不同种子运行每段和每个厚度，作为工程上的独立运行假设。

## 整星同预算对照

输入沿用[整星基准](SPACECRAFT_TID_BENCHMARK.md)中的公开轨迹谱、几何和 0.8 / 2.0 mm 壁厚。未分层和分层各用 **800 万历史**，且每个粒子种类在每种厚度均用 200 万历史。分层设置如下：

| 粒子 | 能段（MeV） | 每种厚度的历史数 |
| --- | --- | ---: |
| 电子 | 0.1–0.5 / 0.5–1.2 / 1.2–3 | 250,000 / 550,000 / 1,200,000 |
| 质子 | 1–8 / 8–20 / 20–100 | 250,000 / 450,000 / 1,300,000 |

最高段分别只占原电子和质子通量的约 0.054% 和 0.051%。为这些段单独分配历史，提高了对能穿透屏蔽的粒子及其次级的抽样频率。

| 舱内靶 | 壁厚 | 电子沉积历史（原 → 分层） | 质子沉积历史（原 → 分层） |
| --- | ---: | ---: | ---: |
| OBC | 0.8 mm | 6 → 1,431 | 3 → 2,606 |
| OBC | 2.0 mm | 5 → 173 | 2 → 1,257 |
| 载荷 | 0.8 mm | 18 → 4,911 | 6 → 9,710 |
| 载荷 | 2.0 mm | 15 → 748 | 2 → 4,476 |

全部 12 个靶区／壁厚组合均生成剂量估计。太阳翼的四个组合各段都有命中，与基线剂量差均小于一个合成标准误（最大 0.76 倍）；它们的 RSE 从约 2.6–2.7% 增至约 4.1–4.4%，反映了预算向舱内信号倾斜。舱内信号采样改善，但 1–8 MeV 质子段在四个舱内靶、两种壁厚下都仍为零命中，因此还不能用完整谱结果验收舱内屏蔽优劣。下一步应验证保留全谱覆盖的混合重要性抽样，或为低能段建立可辩护的独立约束。

## 复现和检查

先完成整星基准的轨道谱生成及 `production` 扫描。以下从源码根目录执行；分层输出目录须不存在：

```powershell
$dir = 'reports/spacecraft-tid-reproduce'
$cli = '.\dist\SpaceRad-0.1.6-local\spacerad_cli.exe'
python tools/stratified_tid.py run --cli $cli --project "$dir/project.json" --scan-settings examples/scans/spacecraft-bus-thickness.json --strata-settings examples/scans/spacecraft-energy-strata.json --output-dir "$dir/stratified" --baseline "$dir/production" --parallel 3
python tools/stratified_tid.py inspect --cli $cli --output-dir "$dir/stratified" --baseline "$dir/production" > "$dir/stratified-offline.json"
```

普通使用可省略 `--baseline`，自建 Worker 可在运行时指定 `--runtime`。每段保留原始输入、标准扫描档案和日志。可用桌面查看任一单段历史扫描；跨段汇总由脚本输出 JSON 和 CSV。当前汇总限靶区 TID，不合并体素场，也未接入桌面配置页。

本地 CTest **42/42** 通过，涵盖切分跨能箱、能量节点、通量／注量归一化及非法分段。实跑的 12 个输运工况逐一离线验收。用原始档案重建的 JSON 与保存结果逐字节相同；修改计划中的历史总数后，离线工具在读取子任务前拒绝。
